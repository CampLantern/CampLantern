# 전투 시스템 구현 지시서 (Claude Code 복붙용) — v0.4 스펙 반영

**Camp & Craft (가칭)** | 스펙 원본: `Docs/전투_시스템_세부_기획서_v0.4.docx` (규칙 전용 — 판정 기법은 CLAUDE.md 판정 규약 소관)

이 문서는 Unity 프로젝트의 터미널(Claude Code)에서 순서대로 붙여넣어 사용하는 프롬프트 모음이다.
각 단계는 **한 세션에 하나씩** 실행하고, 완료 판정을 통과하면 커밋 후 다음 단계로 넘어간다.

> 사전 조건: 기획서 md 파일을 `Docs/전투_시스템_세부_기획서_v0.1.md` 경로에 넣어둘 것.
> 스크립트 예시의 경로·네임스페이스는 프로젝트 컨벤션에 맞게 0단계에서 한 번만 수정하면 된다.

## 0단계 — 프로젝트 규칙 세팅 (CLAUDE.md)

**목적**: 이후 모든 명령에서 "기획서 §X-X"라고만 말해도 에이전트가 스펙을 찾아 읽게 만든다.

```
Docs/전투_시스템_세부_기획서_v0.1.md 를 읽고, 이 프로젝트의 CLAUDE.md를 작성해줘.
포함할 내용:
1. 이 기획서가 전투 구현의 유일한 스펙 원본이며, 모든 전투 코드는 관련 문서 절 번호를
   클래스 상단 주석으로 참조할 것 (예: // Spec: 기획서 §4-3 어그로 시스템)
2. Unity 6 / XR Interaction Toolkit 기반. VR 대상 플랫폼은 Quest.
3. 네임스페이스는 CampCraft.Combat, 스크립트 경로는 Assets/Scripts/Combat/ 하위에
   Weapons / Monsters / Player / Data 폴더로 분류.
4. 밸런스 수치는 전부 ScriptableObject 데이터로 분리하고 코드에 하드코딩 금지
   (기획서 §9의 "수치는 임시값" 원칙 — 나중에 에셋만 바꿔서 튜닝).
5. 네트워크 동기화 코드는 별도 지시 전까지 작성하지 말 것 (§5는 마지막 단계).
   단, 나중에 "클라 감지 → 호스트 적용"으로 분리하기 쉽도록 데미지 적용부는
   이벤트/메서드 한 곳으로 모아둘 것.
6. 각 단계 완료 시 내가 에디터에서 수동으로 해야 할 작업(프리팹, 콜라이더, 씬 배선)을
   체크리스트로 정리해서 알려줄 것.
7. [판정 규약] 모든 히트/접촉 판정에 물리 충돌 콜백(OnTriggerEnter, OnCollisionEnter,
   OnTriggerStay 등)을 사용하지 않는다. 판정 주체가 매 틱 능동적으로 검사하는
   쿼리 방식(스윕/캐스트/오버랩/거리 계산 등)으로 통일한다.
   콜라이더는 쿼리 대상(피격 볼륨 정의)으로만 사용 가능하다.
   시스템별 구체 기법은 네가 선택하되, 선택 근거를 반드시 설명할 것.
   공통 요구사항: 고속 이동체(빠른 스윙, 화살)도 판정 누락이 없어야 한다
   (터널링 금지 — 기획서 §0 판정 신뢰성 요구).
작성 후 CLAUDE.md 내용을 보여줘.
```

**완료 판정**: CLAUDE.md가 생성되고 위 6개 규칙이 반영됨.

## 1단계 — 데이터 스키마 (ScriptableObject)

**의존성**: 없음. 모든 시스템의 기반.

```
기획서 §4-1, §4-5, §1-5(활/화살 데이터)를 기준으로 ScriptableObject 데이터 스키마를 구현해줘.
경로는 Assets/Scripts/Combat/Data/.

- MonsterData: hp 기준값, 활동 반경, 감지 반경, 추격 반경, idleMoveSpeed, chaseMoveSpeed,
  약점 배율(기본 1.5f), List<SkillItem>
- SkillItem (Serializable 클래스 또는 SO — 재사용성 고려해서 네가 판단하고 근거 설명):
  공통 필드 damage, skillType(enum: Point/SelfAoe/Melee/Ranged), cooldown, recoverTime,
  animDuration(시전 시간), hitWindowStart, hitWindowEnd(판정 창 — animDuration 대비 0~1
  정규화 비율. Melee는 start/end 쌍, 나머지 타입은 start=end 단일 시점),
  minEngage, weight(기본 1, 미사용 주석). 타입별 필드는 §4-5 표 그대로:
  Point → maxCastRange, aoeRadius / SelfAoe → aoeRadius /
  Melee → range, 부채꼴 각도 / Ranged → projectileCount, projectileSpeed 또는
  레이저용 castHeight, beamWidth (발사체/레이저 구분 서브타입 필요).
  상태이상 부여 필드는 자리만 만들고 [Header("미사용 - 추후")] 처리.
- MeleeWeaponData: 데미지 계수, vMin, vMax, 내구도 최대치, 수리 단가(임시 0)
- BowData: 탄력성 E(최대값), 내구도 최대치 / ArrowData: 무게 W, 가격(임시 1)

각 SO에 CreateAssetMenu 어트리뷰트를 붙이고, Assets/Data/Combat/ 에 테스트용 에셋을
임시값으로 1개씩 생성해줘 (테스트 몬스터는 근거리 Skill1 하나만 보유).
ID/primary key 필드는 지금 넣지 말 것 (기획서 방침 — 정식 스키마 때 일괄 부여).
```

**완료 판정**: 컴파일 통과 + 테스트 에셋 생성 + 인스펙터에서 타입별 필드가 skillType에 맞게 보임.

**커밋**: `feat: combat data schema (SO) — 기획서 §4-1, §4-5, §1-5`

## 2단계 — 근접 무기 유효타 판정

**의존성**: 1단계.

```
기획서 §1-2, §1-3의 근접 유효타 판정을 구현해줘.

- MeleeWeapon.cs (Assets/Scripts/Combat/Weapons/):
  무기 단위 상태머신 Idle → 공격 → 마무리 → Idle.
  접촉 감지는 CLAUDE.md 판정 규약(물리 콜백 금지, 능동 쿼리)에 따라 네가 기법을
  선택하고 근거를 설명해줘. 고속 스윙에서도 판정 누락이 없어야 한다(터널링 금지).
  속도 측정도 물리 엔진 velocity에 의존하지 말고 자체 계산(예: 프레임 간 위치 차분)
  기반으로 — 기법은 네 선택, 근거 설명.
- 데미지 공식: clamp(속도, vMin, vMax) × 데미지 계수 × 0.25f (상수도 WeaponData로).
  vMin 미달이면 무효타 — 데미지 0이며 피격 사운드/이펙트/햅틱 훅을 호출하지 않는다.
- 판정 규칙 (§1-2): 몬스터별 첫 접촉 1회. 접촉이 연속되어도 대상이 다르면
  각각 새 공격으로 처리. 같은 몬스터의 몸통→머리 훑기는 첫 접촉 부위만 인정.
  해당 몬스터와의 접촉에서 완전히 벗어난 몬스터는 재공격 가능 목록으로 복귀.
- 약점: 머리 부위 적중 시 MonsterData의 약점 배율 적용. 머리 부위 식별 방식
  (별도 쿼리 대상 볼륨, 본 기준 반경 등)은 규약 내에서 네가 선택하고 근거 설명.
  약점 적중 여부를 데미지 이벤트에 포함시켜서 나중에 어그로 시스템이 구독할 수 있게.
- 유효타 시 내구도 1 차감. 내구도 0이면 OnWeaponBroken 이벤트 발행
  (홀스터 귀환 처리는 7단계에서 연결 — 지금은 이벤트만).
- 데미지 적용은 IDamageable 인터페이스 + ApplyDamage(HitInfo) 한 곳으로 모을 것
  (CLAUDE.md 규칙 5 — 나중에 네트워크 분리 지점).

테스트용 DummyMonster.cs를 만들어서 HP, 피격 로그(속도/데미지/약점 여부)를
콘솔에 출력하게 해줘. 완료 후 에디터 수동 작업 체크리스트를 정리해줘
(무기 프리팹의 타격부 기준점 세팅, 몬스터 피격 볼륨 세팅, XR Grab 연결 등).
```

**완료 판정**: 더미 몬스터에 휘두르면 속도 비례 데미지 로그, 살살 대면 무효타(로그 없음/무효 표시), 머리 적중 시 ×1.5.

**커밋**: `feat: melee valid-hit & velocity damage — 기획서 §1-2, §1-3`

## 3단계 — 몬스터 FSM (Idle / Chase / Return)

**의존성**: 1단계. (2단계와 병렬 가능)

```
기획서 §4-4의 몬스터 상태머신을 구현하되, 이번 단계는 Idle / Chase / Return
세 상태만. Attack과 Exhausted는 5단계에서 추가한다.

- MonsterController.cs (Assets/Scripts/Combat/Monsters/):
  상태 패턴으로 구현 (enum + switch 금지, 상태 클래스 분리 — 5단계 확장 대비).
- Idle: MonsterData의 활동 반경 내 랜덤 지점을 골라 idleMoveSpeed로 배회.
  도착하면 잠시 대기 후 다음 지점.
- 감지: 플레이어가 감지 반경 진입 시 Chase 전환. Chase 중 chaseMoveSpeed로 타겟 추적.
- Return: 타겟(가장 가까운 플레이어)이 추격 반경 밖이면 즉시 진입.
  Return 중에는 무적(모든 ApplyDamage 무시) + 어그로 무시,
  원위치(스폰 지점) 도달 시 HP 전량 회복 후 Idle 복귀.
- 오버레이 상태(Stunned/Death)를 위한 레이어 구조를 지금 잡아둘 것:
  메인 상태와 독립적으로 적용되는 IOverlayState 인터페이스 + Death 구현
  (HP 0 → 모든 상태 즉시 종료, 사망 처리). Stunned는 구조만, 구현은 보류.
- 현재 메인 상태를 SerializeField 문자열로 노출해서 인스펙터에서 확인 가능하게.
- 이동은 NavMeshAgent 사용 여부를 네가 판단하고 근거를 설명해줘
  (사냥터 존이 작고 지형이 단순하다는 전제).

2단계의 DummyMonster를 이 컨트롤러 기반으로 교체하고,
에디터 수동 작업 체크리스트(NavMesh 베이크 여부, 스폰 지점 등)를 정리해줘.
```

**완료 판정**: 배회 → 접근 시 추격 → 멀어지면 귀환(무적·HP 회복) 사이클이 씬에서 확인됨.

**커밋**: `feat: monster FSM (Idle/Chase/Return + overlay layer) — 기획서 §4-4`

## 4단계 — 어그로 시스템

**의존성**: 2, 3단계.

```
기획서 §4-3의 어그로 시스템을 구현해줘. AggroController.cs로 분리하고
MonsterController가 타겟을 여기서 조회하는 구조로.

규칙 6개를 전부 구현:
1. 기본 타겟팅: 가장 가까운 플레이어. 재계산 트리거는 "새로운 공격(유효타)이 들어올 때".
2. 히스테리시스: 현재 타겟보다 X미터 이상 가까워야 타겟 전환 (X는 MonsterData 필드로
   추가, 임시 2m). 프레임 단위 타겟 튐 방지 목적.
3. 약점 고정: 약점(머리) 유효타 시 해당 플레이어에게 5초 어그로 고정
   (5초도 데이터 필드, 임시 5f).
4. 감쇄: 고정 중 다른 플레이어가 약점 타격 시 잔여 고정시간 −1.5초 (필드, 임시 1.5f).
5. 감쇄 소진: 잔여 시간이 0 이하가 되면, 그렇게 만든 마지막 공격자에게 신규 5초 고정.
6. 리셋: 가장 가까운 플레이어가 추격 반경 밖이면 무조건 즉시 리셋 (약점 고정보다 우선)
   → Return 진입. 타겟 다운 시 즉시 재계산 (다운 시스템은 7단계 — 지금은 훅만).

2단계의 약점 적중 이벤트를 구독해서 동작하게 연결하고,
디버그용으로 현재 타겟과 고정 잔여시간을 인스펙터/기즈모로 표시해줘.
```

**완료 판정**: 2인 테스트(또는 더미 플레이어 2개)에서 근접 타겟팅·약점 고정·감쇄·소진 시 타겟 스틸이 로그로 확인됨.

**커밋**: `feat: aggro system (proximity + weakpoint lock/decay) — 기획서 §4-3`

## 5단계 — 스킬 시스템 + Attack / Exhausted

**의존성**: 3, 4단계.

```
기획서 §4-5~§4-7을 구현해줘. FSM에 Attack과 Exhausted 상태를 추가한다.

- 스킬 선택 (§4-7): Chase 중 매 판단 틱마다
  후보 = skillList 중 (쿨타임 완료) AND (거리 조건: 타겟 거리 ≥ minEngage,
  Melee/Point는 사거리 내). 후보 있음 → 균등 랜덤 1개 시전(Attack 진입).
  후보 없음 + 타겟 사거리 내 → Exhausted. 후보 없음 + 사거리 밖 → Chase 유지.
  중복 방지 로직은 만들지 말 것. weight는 필드만 읽고 로직은 균등 랜덤 유지.
- Attack: animDuration 동안 스킬 시전(타이머 기반) → 종료 후 recoverTime 동안
  Recover(무방비) → 재판단. 애니메이션이 아직 없어도 animDuration 임시값으로
  동작해야 하며, 클립 확정 후 animDuration을 클립 길이로 자동 동기화하는
  헬퍼(클립 길이 읽어 덮어쓰기)를 만들어둬.
- Exhausted: 지속시간 = 가장 빨리 도는 스킬의 잔여 쿨타임(런타임 계산).
  이동 정지, 피격 정상 적용. 탈진 중 타겟이 추격 반경 이탈하면 탈진을 끊고 Return.
- 판정 (§4-6, hit window 방식): CLAUDE.md 판정 규약 준수 (물리 콜백 금지, 능동 쿼리).
  이번 단계는 Melee 타입만 실동작 — 공격 부위 기준의 판정 검사를
  EnableHitCheck()/DisableHitCheck()로 캡슐화하고, 활성 구간 동안 매 틱 쿼리
  (기법은 네가 선택: 전방 부채꼴 거리·각도 수학 판정 권장, 근거 설명).
  Attack 타이머의 경과 비율이 hitWindowStart에 도달하면 Enable,
  hitWindowEnd에서 Disable. 애니메이션 이벤트는 사용하지 않는다.
  안전장치: Attack 상태의 Exit 처리에서 판정을 무조건 Disable
  (Stunned 취소 시 판정 잔류 방지 — 기획서 §4-6 안전장치 규칙).
  시전당 플레이어별 최대 1회 피격. 나머지 타입(Point/SelfAoe/Ranged)은
  클래스 골격과 TODO 주석만 만들어둬 (이들은 hitWindowStart=End 단일 시점 판정.
  Point/SelfAoe는 폭발 시점 범위 내 거리 판정, 발사체는 이동 경로 기반 판정 예정).
- Stunned 오버레이를 이번에 실구현: 메인 상태 타이머 일시정지, 진행 중 공격 취소,
  해제 시 Chase 복귀. Exhausted 위에도 적용됨을 테스트 코드로 확인.

플레이어 피격은 임시 PlayerHealth.cs(HP + 피격 로그)로 받게 하고,
에디터 수동 작업 체크리스트(공격 부위 기준점/판정 파라미터 세팅 등)를 정리해줘.
애니메이션 이벤트 태깅은 필요 없다 — 판정 타이밍은 전부 데이터(hit window)로 처리한다.
```

**완료 판정**: 스킬 1개 몬스터가 "추격 → 공격 → 탈진 → 추격" 리듬으로 동작하고, 탈진 중 프리딜 가능.

**커밋**: `feat: skill system + Attack/Exhausted states — 기획서 §4-5~4-7`

## 6단계 — 활 / 화살

**의존성**: 1단계. (3~5단계와 병렬 가능)

```
기획서 §1-4(활/화살 계산식·회수 규칙)를 구현해줘.

- Bow.cs / Arrow.cs (Assets/Scripts/Combat/Weapons/):
  발사 속도 v0 = E(탄력성) × d(당김 비율 0~1) − c × W(화살 무게).
  c는 전역 밸런스 상수 SO(CombatBalanceData 등)로 분리.
  당김 비율은 시위를 잡은 손과 활 그립 간 거리로 계산 (XR 양손 인터랙션 —
  구체 연결은 수동 작업 체크리스트로).
- 화살 비행/판정: CLAUDE.md 판정 규약 준수 — 명중 감지는 물리 콜백이 아닌
  이동 경로 기반 쿼리로 (기법은 네 선택, 근거 설명). 빠른 화살도 판정 누락 금지.
  중력 궤적은 유지하되(물리 시뮬레이션 이용 여부는 네 선택 — 판정만 규약 준수),
  접촉 시점의 화살 실제 속도 v를 실측.
- 화살 데미지: clamp(v, vMin, vMax) × K × (1 + b × W). K, b, vMin, vMax도 밸런스 SO.
- 약점 배율은 근접과 동일 규칙 적용. 발사 1회당 활 내구도 1 차감.
- 화살 소지: 최대 30발(밸런스 SO 필드), 발사 시 차감.
- 명중 시 화살은 몬스터에 박힌 상태로 고정(부모 연결). 빗나가서 지면 등에 닿으면 소멸.
- 회수: 박힌 화살과 플레이어 손의 거리 판정(상호작용 반경은 밸런스 SO)으로
  접촉 인식 시 즉시 회수 — 박힌 화살 오브젝트 제거 + 소지 수량 +1 +
  화살집 비주얼 갱신 훅 호출.
  단, 소지 30발 만땅이면 무반응. 몬스터 사망 후에도 박힌 화살은 유지되고 회수 가능
  (사망 처리 시 화살 오브젝트를 파괴하지 않도록 주의).

에디터 수동 작업 체크리스트(활 프리팹, 시위 비주얼, 화살집, XR 인터랙션 연결)를 정리해줘.
```

**완료 판정**: 당김 정도에 따라 초속 변화, 중력 낙차 확인, 명중 시 무게 보너스 데미지, 박힌 화살 회수/만땅 무반응 동작.

**커밋**: `feat: bow & arrow (draw-based velocity, retrieval) — 기획서 §1-4`

**의존성**: 2~6단계.

```
기획서 §2(플레이어 전투 규칙), §4-2(HP 스케일링), §1-5~§1-6(내구도 귀환/홀스터), §3(기여)을 구현해줘.

  취소 없음), 전멸(전원 다운 → 사냥 실패 → 지정 Scene 로드, Scene 이름은 설정값).

  기계 효과는 기절=입력 잠금(머리 회전은 자유 — VR 멀미 방지 주석 명시),
  독=틱 데미지 코루틴. 지속시간/틱 수치는 SO 필드로 자리만.
- HP 스케일링 (§4-2): 몬스터별 기여자 Set 관리. 신규 플레이어의 첫 유효타 시점에
  최대 HP를 기준 × (1 + 0.5 × (인원−1))로 갱신하고 증가분을 잔여 HP에 플랫 가산.
  감소 없음. 계수 0.5는 밸런스 SO.
- 기여 판정 (§3): 유효타 1회 이상 = 기여. 사냥 성공 시 기여자 목록 이벤트 발행
```

## 운영 팁

- **한 세션 한 단계.** 단계 중간에 다른 시스템을 덧붙이지 말 것. 추가 요구가 생기면 완료 판정 → 커밋 → 새 명령으로.
- **막히면 절 번호로 되물을 것.** "그건 기획서 §4-3의 감쇄 소진 규칙이랑 충돌하는데, 문서 다시 읽고 수정해줘" 식으로 스펙을 심판으로 쓰면 에이전트의 임의 판단을 줄일 수 있다.
- **컴파일 확인 습관**: 각 단계 끝에 `Unity 배치 모드로 컴파일 에러만 확인해줘` 를 붙일 수 있다 (CLI 라이선스/경로 문제로 실패하면 에디터에서 직접 확인).
- **수치 튜닝은 코드 수정이 아니라 에셋 수정.** 1단계에서 SO로 분리해둔 이유. 플레이테스트 후 v_min, 계수, 반경 값은 에셋에서만 바꾼다.
- **기획서가 바뀌면**: md를 갱신하고 `기획서가 vX.X로 갱신됐어. 변경점을 diff로 파악하고 영향받는 코드를 목록으로 뽑아줘` 부터 시작.
